Why “Predicted values must be in range [0, 1]” Happens & Automated Fix

The DrivenData validator checks raw band values prior to masking; NaN, ±Inf, float32 nodata sentinels like -3.4028235e+38, or unclipped scores <0 or >1 trigger Predicted values must be in range [0, 1]. Every *-zeros.tif served by this repository is automatically gated by gems/gates.py + vendor/gems57/validate.py + scripts/check_site.py:

import numpy as np, rasterio
with rasterio.open("raw_prediction.tif") as src:
    arr = src.read(1).astype("float32"); prof = src.profile.copy()
arr = np.nan_to_num(arr, nan=0.0, posinf=1.0, neginf=0.0)
arr[arr < -1e30] = 0.0
arr = np.clip(arr, 0.0, 1.0).astype("float32")
prof.update(dtype="float32", count=1, nodata=None, compress="deflate")
with rasterio.open("clean_submission-zeros.tif", "w", **prof) as dst:
    dst.write(arr, 1)
