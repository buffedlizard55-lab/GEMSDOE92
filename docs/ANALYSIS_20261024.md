## 1. Why did `h33-h33-2-b2` score 0.2778 — line by line?

`h33-h33-2-b2` (GEMSDOE32, 2026-10-04T22:00:00Z, uuid `e5eb6e7e`) is an
**owner-reported CLAIM**, not an organizer receipt
(`registry/parents/R0.json`: `receipt: null`;
`ledger/submissions.csv`: zero RECEIPT rows). Subject to that label, the
file itself and its lineage explain the result. Every structural claim
below was re-measured this session from the rasters:

| Ancestor (repo lineage) | CLAIM | What changed | Measured structure |
|---|---|---|---|
| H19-5 | 0.1922 | multi-line corroborated potential-field ridge skeleton ("worms") | superset skeleton; this session verified R0 ⊂ SOLO ⊂ D2.8 ⊂ H19 **exactly**, pixelwise |
| D2.8 | 0.2600 | Poisson-disk thin at 2.8 px | spacing floor; R0 final min nearest-neighbour = 2.828 px |
| SOLO | 0.2708 | drop sub-bar dots (solo deletions), catalogue distance > 1 px | ancestor mask recovered from bridge raster |
| **B2 = R0** | **0.2778** | keep > 2 px off known traces | 37,654 unit dots; min d_cat 2.236 px; **zero** mass on catalogue; 2,171 dots in the ≤ 3 px collar; EPSG:32611, 3730×3292 @ 100 m; footprint 5,167,373 cells; sha256 zeros `c55bafc4…ab6fa9`, NaN `baeae321…7c77dd` (rebuilt byte-identically this session) |

The mechanism is the DTI algebra, not luck. The official metric
(DrivenData #306, problem-description p. 967 — fetched in full this
session) is

`DTI = TPw / (TPw + α·FPw + β·FNw + ε)`, α = 0.2, β = 0.8,

with triangular kernel `k(d) = max(1 − d/R, 0)`, R = 300 m = 3 px,
max-pooled on both sides, and the parent sits at total mass S = 37,654.
At fixed S: (a) two dots whose kernels overlap the same truth pixel earn
credit once but both pay toward FP-side mass — thinning removes that
redundancy; (b) dots on/near the known catalogue cannot earn credit
because known faults are masked from the live truth — the B2 clearance
spends mass only where undiscovered truth can exist; (c) because
β (0.8) ≫ α (0.2), *removing* a dot only helps when its marginal
expected credit is below a low bar (~α·DTI/(1−DTI)-scale) — which is why
the SOLO prune to a hard budget, rather than the dense skeleton, won.
Each lineage step is monotone in exactly the direction the algebra
predicts: 0.1922 → 0.2600 → 0.2708 → 0.2778. The historical portal
error ("Predicted values must be in range [0, 1]") is an encoding
failure (NaN/sentinel or over-range values inside the footprint); the
zeros-outside TIFs are all-finite in [0, 1] and are the portal-safe
encoding this repo serves first.

Two composition facts limit what R0 can earn (both measured here):

1. **R0 spends 94.2 % of its budget > 3 px from the catalogue.** Only
   2,171 / 37,654 dots (5.8 %) sit in the ≤ 3 px collar, yet in the
   locally computable *proxy-diagnostic* (fixed full catalogue,
   catalogue NOT masked — biased upward for collar dots) those 2,171 collar
   dots earn essentially all of the locally visible credit: R0's
   whole-file TP_w there is 378.0 and its dots > 3 px from the catalogue
   contribute only a few % of it. On the real board the catalogue is
   masked, so the collar earns only where the expert's *new* truth lies
   near an old trace — and the 94.2 % far mass earns only where a truly
   unmapped fault crosses the worm skeleton. R0 is a bet on both
   discovery channels simultaneously, placed by physics-corridor
   geometry, never ranked by any per-dot likelihood.
2. **R0's thinning is scan-order, not evidence-ranked.** Which skeleton
   pixels survive is decided by scan position, so the surviving dot set
   is generic: any re-ranking by a real per-dot signal, if it exists,
   must weakly dominate it in expected credit per dot. That is the
   opening every lane in this repo attacks. The catch (inherited
   finding): pure re-ranking/re-emission *within* the skeleton stays
   99.37–99.40 % within 3 px of R0 = a literal duplicate in behaviour.

## 2. What the board actually measures (official, re-verified)

- Truth = newly identified faults mapped by experts, **absent from the
  public USGS/INGENIOUS catalogue**; region chunked into public/private
  splits. Initial Prize Round: scored on the private set. Final Round:
  experts expand labels using all submissions; **the same one chosen
  submission is rescored** against the expanded set
  (top-5 $100K/$70K/$40K/$25K/$15K). A submission with *mappable,
  geologically defensible* expressions therefore keeps earning in the
  Final Round where label expansion adds exactly the class of lineaments
  experts can defend — visible scarps on high-resolution DEMs (the repo
  ships `1m_DEM_links.csv`; the experts' instrument is plainly terrain).
- Forum guidance (second-hand through web search; re-fetch before
  treating as organizer law): known faults are masked pixel-exactly with
  no buffer; "new fault" includes newly mapped geometry of an existing
  fault system (tip extensions, splays, parallel strands).
- Prizes/deadline: Initial Round work proceeds under the weekly
  submission-slot discipline recorded in `SLOT_PLAN.md`; repo deadline
  note = 2026-12-03.

## 5. Verdict

Pre-registered promotion rule (mechanism card + session protocol):
promote only if HOLDOUT-DTI beats the current holdout best AND the file
passes literal uniqueness AND format gates. f45Ltop passes uniqueness
and gates, beats the parent with CI excluding 0, but does **not** beat
RELIEF p10's 0.006045. **Verdict: negative — NOT_CLEARED for a weekly
slot.** The discontinuity is geological, not statistical: the holdout
can only hide catalogue faults, so it prices *rediscovery of catalogue-
style faults* (where RELIEF's near-skeleton re-ranking excels and is
simultaneously unsubmittable as a duplicate), while the live test prices
*new mapping*, where the independent SGMC control says off-skeleton
structural lines carry real fault signal that every skeleton arm
sacrifices. No local instrument can resolve that disagreement — only an
organizer receipt can, and the programme has zero receipts to date
(Blocker 0). Whether to spend one of the remaining weekly slots as a
*calibration* measurement on the only literal-unique, parent-dominating
file the repo has produced is a human portfolio decision; this session's
obligation is that the file is format-valid, honestly labelled and one
click away.
