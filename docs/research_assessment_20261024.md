# GEMS research assessment — 2026-10-24

## Decision in one sentence

**No candidate GeoTIFF was built, validated, promoted, or uploaded.** The selected future lane is a depth-stratified USGS magnetotelluric (MT) conductance-break test, but the literal shared uniqueness gate has a verified universal blocker: one public, same-grid probability raster is positive at every legal pixel, so every non-empty prediction has 100% forward dot overlap with it (`>70%` stop threshold). This blocks every geological lane before placement, not just the selected one.

The blocker and its reproduction are in `evidence/registry_saturation_blocker.json`; the public path inventory and scan code are in `registry/public_gems_tif_inventory.json` and `scripts/scan_public_gems_tif_registry.py`. The witness bytes are cached only under ignored `.cache/public_gems_tifs/` and are not committed.

## Evidence audit: what does `0.2778` mean?

- The current checkout's `ledger/submissions.csv` contains **21 `BUILT` rows and zero `RECEIPT` rows**. The `0.2778` value attached to `h33-h33-2-b2` is therefore an owner-reported **CLAIM**, not `ORGANIZER-CONFIRMED`.
- The parent is a catalogue-flank removal: `h33-h33-2-b2` is a 37,654-dot descendant of the H27-4/R0 line. Its B2 recipe removes points within two pixels of the published catalogue; it does not add a new geological detector. A plausible mechanism for a higher public score is reduced mass near known faults and fewer redundant/low-credit points, but this is only a mechanistic explanation—not a causal attribution or a verified score.
- The public GEMSDOE32 project page labels its H33-2-B2 artifact **UNSCORED** and says no organizer score exists for repository artifacts. Its `0.2708` base and `0.2747` projection are project-page values, not receipts. The local H33-2 record also contains model-calibration values; those are not competition receipts.
- At the time of the official leaderboard check on 2026-10-24, the public display showed `0.4413`, `0.3916`, and `0.3904` at ranks 1–3. This conflicts with the user-provided `0.3195` snapshot. The display is a public-leaderboard observation, not proof of any account's receipt or private score.
- Accordingly, neither `0.2778` nor a better organizer score is supportable from the artifacts inspected. No upload was made, no weekly slot was used, and no organizer receipt was copied into the ledger.

## Existing holdout evidence (historical, not a new run)

`evidence/relief_proxy_audit.json` contains a previously recorded catalogue hide-and-recover evaluation. It is an internal known-catalogue proxy, not an organizer score and not a fresh run for the selected MT hypothesis:

- `HOLDOUT-DTI`, evaluator `gems57-pooled-hide-v2`, **22,663 withheld positives**: R0 `0.004006` (95% CI `[0.003424, 0.004690]`).
- `HOLDOUT-DTI`, same evaluator and positives: `RELIEFp10piedmont` `0.006045` (95% CI `[0.005187, 0.006927]`).
- Paired `HOLDOUT-DTI` difference, `RELIEFp10piedmont − R0`: `+0.001967` (95% CI `[+0.001483, +0.002504]`), 157 spatial clusters, 1,000 bootstrap draws.

This direction is encouraging only for that local proxy. The evaluation re-scores fixed descendant rasters; it is not a fold-wise retraining of the historical R0 lineage. The local irregularities also document weak comparability between catalogue proxies and live/hidden truth. These numbers do not establish that a better competition prediction is supportable.

### Selected lane and stop point

The only lane that would be tested next is Rank 1: **depth-stratified USGS MT conductance discontinuities**. It would not use catalogue-derived features; the fold builder would still hide whole buffered components, and visible faults would be pixel-exactly masked by the shared evaluator. Every feature would be tested alone as a leakage canary before any combination; `AUC > 0.90` would be treated as leakage until explained.

Before downloading or engineering that surface, the shared pre-placement uniqueness gate was run against a hash-verified public candidate-like TIFF. It proves that **every non-empty prediction in the legal output domain has forward dot overlap 1.0** with the 17GEMSDOE full-support surface. The specified stop is `>0.70`. Because this is a method-independent blocker, the run stopped before candidate feature construction, holdout evaluation, point placement, or use of `vendor/gems57/submission_writer.py`. The top hypothesis therefore has no holdout score, CI, candidate SHA, format receipt, submission name, or slot decision.

This decision follows the current literal shared rule (“against any registry raster”). A different interpretation—Spearman for continuous surfaces but dot-overlap only for discrete point rasters—would change the gate and must be explicitly approved before any new candidate is built. No candidate was uploaded.
