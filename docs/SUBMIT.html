Submit in five steps

  1. Download the .tif above (or the ZIP that contains exactly that one TIFF). Do not open and re-save it in GIS software; any re-save changes the bytes the audit certifies.
  2. Sign in at DrivenData and open the submission form.
  3. Choose the file. If the form shows a separate name field, paste the submission name; if it shows only a note field, paste the note — it begins with the lane name and the file name carries the content id.
  4. Paste the note (≤ 140 characters, already checked). Send.
  5. When the receipt appears, enter the score exactly as shown in ledger/raw_paste.txt / ledger/submissions.csv as an ORGANIZER-CONFIRMED receipt. Never infer a score from the local HOLDOUT-DTI or from the MODEL projection.

Why "OK TO SUBMIT" and "slot verdict" differ

OK TO SUBMIT = format-valid ∧ unique under the decisive tier (S) ∧ leakage canary passes ∧ model kill-criterion not triggered. Slot verdict = the protocol's promote/negative: the paired HOLDOUT-DTI difference against the repository's recorded holdout best must be entirely above 0. The two are independent on purpose: the first says the portal will accept the file and it is not a copy; the second says whether the project's own pre-registered rule recommends a slot. The holdout instrument rewards recovery of mapped catalogue faults — which the real scorer masks — so its verdict and the leaderboard can disagree (see analysis).

Literal all-registry rule (Tier T): NOT passed. It cannot be passed by any file at all because blanket rasters overlap everything; the policy and the one-line switch to change the decisive tier are in UNIQUENESS_POLICY_20261024.md. Both tiers S and L are measured and shown on the main page.
