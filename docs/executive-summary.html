Why this file fixes the “Predicted values must be in range [0, 1]” error

The portal validates that every cell in the GeoTIFF is finite and in [0, 1]. Earlier research artifacts used NaN outside the footprint (legacy encoding from the competition's sample submission, which has 7,111,787 NaN cells outside its 5,167,373-pixel footprint). The current portal (late 2025) rejects any NaN as out-of-range. GAPBRIDGE-V2 uses zeros outside the footprint (all 7,111,787 outside cells are exactly 0.0, all 5,167,373 inside cells are finite 0.0 or 1.0) and is verified to have 0 NaN/Inf anywhere, so it passes the strict require_submission_encoding check (all_finite=True global_range=[0.0,1.0] zero_outside=True).

It also respects the catalogue collar: 0 dots on mapped faults and 0 dots within 2 px (200 m) of a mapped fault (strict d_cat > 2), satisfying the organizer's rule that a prediction near a known trace far from any new truth is penalized.
