3. Why did h33-h33-2-b2 (GEMSDOE32) score 0.2778 — and can we beat it?

Short answer: it won by submodular dot economics, and no — with data available in this sandbox we cannot generate a unique submission projected above it. The 0.2778/0.2784 pair is an information ceiling for this data regime.

3.1 The mechanism (verified against the official metric)

  1. The metric rewards sparse dots, not surfaces. DTI = TPw / (TPw + 0.2·FPw + 0.8·FNw) with a 300 m triangular kernel. TPw saturates per truth pixel (max over the kernel disk), while FPw grows linearly with emitted mass. A continuous skeleton (H19-5, 121,131 px, CLAIM 0.1922) places 3–5 adjacent pixels inside one kernel disk — 4 of them pay full FP cost for zero marginal coverage.
  2. Thinning captured that free lunch: 2.8-px Poisson thinning (d2-8, 44,090 dots, 0.2600) cut ~64 % of FPw while keeping >91 % of corridor coverage (+0.068 CLAIM).
  3. Collar pruning captured the second: dots within 2 px of the mapped catalogue sit in the digitisation halo of faults the evaluator masks out — they are pure FP. Pruning them (d_cat > 2 px → 37,654 dots) added +0.0178 → 0.2778 (h33-2-b2).
  4. Two-regime natural experiment (this repo, 2026-10-29): lbmc1 (0.2784) put 98.45 % of its dots at d_cat > 15 px and still tied R0 (41.6 % proximal). Both scores ≈ 0.278 ⇒ hidden faults occupy proximal splays and distal intrabasin corridors — but no available feature set localises either regime well enough to exceed ~0.28.

3.2 Why we cannot beat 0.2778 uniquely right now

  • Experiment 3 (this session) proved the family is closed: any consensus re-derivation of the scored G-set overlaps it 0.98–1.00 before pruning and 0.80 after — the duplicate rule stops it (measured, run card filed).
  • External-stack learning (experiments 1–2) does not close the gap: a supervised fault-appearance model on the free official stack (GeoDawn + 3DEP LiDAR + SGMC + GDR vents/wells/probes) reaches fold-proper HOLDOUT-DTI 0.0437 vs the R0 recipe's 0.0967, and external-stack submissions across the whole fleet score 0.02–0.225.
  • The live leaderboard has moved: as of 2026-10-31 the leader is 0.4544 (xiaofanhu, 35 submissions), and rank #20 is 0.3417. Those teams train segmentation models (U-Net family — see the official reference solution) on the full multi-band numeric_features.tif stack that requires DrivenData auth to download. That stack is the single missing asset between 0.28 and 0.35+.
What would beat 0.2778 (ranked by expected gain): (1) the competition's numeric_features.tif (free with a DrivenData login — place in data/, then the U-Net/GBDT pipeline trains; the dropbox mirror gems-geodawn-numerical-features.tif linked in the session prompt is the same asset); (2) full-resolution (not u8-quantised) GeoDawn grids from USGS ScienceBase DOI 10.5066/P93LGLVQ; (3) 1-m 3DEP LiDAR processing beyond the 12 quantised channels. 4. How to make a submission — exact steps (executive-summary subpage)

  1. Download one .tif above. The generated file is single-band float32, EPSG:32611, 3292×3730, values only in {0.0, 1.0}, zeros outside the footprint.
  2. Open drivendata.org/competitions/306/competition-doe-gems → Submit (login required).
  3. File to submit: choose the .tif (or its one-TIFF .zip). The form accepts a single-band GeoTIFF or a .zip containing exactly one GeoTIFF.
  4. Note (optional but recommended): a ≤140-character comment. For today's file use: V-GFP vgfp2r: 37654 dots, GeoDawn+LiDAR+SGMC GBDT + vent/well/probe thermal proximity; HOLDOUT-DTI 0.0437 vs R0ctrl 0.0967.
  5. Suggested submission name: gemsdoe92-vgfp2r-37654d-bcb3d2af
  6. Weekly cap: the portal limits submissions (3 per week) — every upload spends a slot; promotion is a selector decision, never automatic.
  7. If the form says “Predicted values must be in range [0, 1]”: the uploaded raster contains NaN (typically outside the footprint) or values outside [0, 1]. The fix is exactly what this pipeline does automatically — write 0.0 everywhere outside the footprint and keep every value in [0, 1]. Never upload a “-nan” encoding. Full guide: docs/how-to-submit.html.
  8. Record the receipt (name + score + date) in ledger/submissions.csv as ORGANIZER-CONFIRMED when the score appears — that is the only evidence class that upgrades a projection.
