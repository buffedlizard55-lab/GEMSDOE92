2. Why h33-h33-2-b2 (GEMSDOE32) reportedly scored 0.2778 — verified from bytes

The lineage was proved by pixel algebra on SHA-256-pinned rasters, not inferred from filenames. Exact XOR counts recomputed this session:

  • GEMSDOE25 D2.8 ≡ GEMSDOE30 d28 — XOR = 0 pixels.
  • GEMSDOE28 SOLO ≡ GEMSDOE31 solo — XOR = 0 pixels.
  • SOLO ≡ D2.8 ∧ (d_cat > 1 px) — XOR = 0; it removed 3,891 dots that hug mapped traces.
  • R0 (0.2778) ≡ D2.8 ∧ (d_cat > 2 px) — XOR = 0; it removed 2,545 more (total 6,436 within 2 px).
  • GEMSDOE36 PINN ⊃ R0 exactly (True) plus 1,200 added dots — and its reported score fell to 0.2750.

Mechanism. The metric is a distance-weighted Tversky index with α = 0.2 (false-positive mass), β = 0.8 (missed truth), and a 300 m triangular kernel applied as a pointwise max. Three consequences explain the whole climb 0.1922 → 0.2477 → 0.2600 → 0.2708 → 0.2778:

  1. Thin the skeleton. With a max-kernel, a second dot next to the first earns almost no extra true-positive credit but still pays false-positive mass. Re-spacing a 1-px skeleton at ≈2.8 px keeps most of the corridor credit at roughly a third of the emitted mass (0.1922 → 0.2600).
  2. Delete the catalogue collar. Mapped fault pixels are masked before scoring, so a dot 100–200 m from a mapped trace is nearly all cost and almost no credit; removing those dots raised the score twice (0.2600 → 0.2708 → 0.2778).
  3. Do not add dots. GEMSDOE36's +1,200 dots lowered the reported score, which is the same mechanism seen in reverse.

What this does NOT mean. The score is not evidence of blind-fault discovery: on the hide-and-recover instrument the same raster scores only 0.004006. It recovered already-mapped faults at a kernel-favourable budget. That is why copying it cannot be the strategy — and why the 0.2778 figure itself is a CLAIM, not a receipt.

4. How the score estimate is produced (and how good it is)

Estimator: ridge logit(E[DTI]) ~ 1 + frac_h19_near3 + frac_dcat_le2 + log10(n_dots) + quadrant_imbalance, fitted by ridge regression in logit space on 107 owner-reported CLAIMs that resolve to exactly one pixel-verified raster (16 further claims could not be matched unambiguously and were excluded, never guessed).

Feature Standardised coefficient Why it belongs
frac_h19_near3_clipped_0.65+5.591 share of dots within 3 px of the H19-5 skeleton — the single strongest empirical signal across 121 claims
frac_dcat_le2-5.757 dead mass inside the masked catalogue collar (pure false-positive cost)
log10_n_dots+1.354 emission budget; more dots help only while each still buys kernel coverage
quadrant_imbalance-3.335 concentration penalty (a file packed into one corner cannot recover a province-wide truth set)

Honesty metrics. in-sample RMSE 0.0672 · leave-one-out RMSE 0.0722 · leave-one-out Spearman 0.750 against the CLAIM values. The LOO RMSE is the ± shown next to every estimate in §3. Known residual structure: the model over-predicts H19-5 descendants by up to 0.14 and under-predicts some independent-physics lanes by up to 0.11 (see the delta column in evidence/score_estimator_20261026.json), because the relationship between skeleton proximity and score is saturating and non-linear with only 107 labelled points. Never read a MODEL number as a leaderboard result.
